# MollyStudio

Редактор Minecraft GUI и пиксельной графики на Electron. Версия пакета — 1.3.0, версия Windows — 1.3.0.0.

## Запуск и проверки

```powershell
npm install
npm start
npm test
npm run test:electron
npm run test:scenarios
npm run test:visual
npm run audit
```

`npm start` открывает текущий исходный код. Для разработки используйте его.

- `npm test` — модульные проверки, сценарии сохранения, восстановления, истории, тем и инструментов.
- `npm run test:electron` — сценарии в настоящем Chromium с отдельным временным профилем в системной временной папке. Открытые пользовательские проекты не используются. Диалоги выбора пути и Discord заменены тестовыми обработчиками; запись файла, IndexedDB, Canvas и код редактора настоящие.
- `npm run test:scenarios` — цепочки выделения и трансформации с отменой, чтение сохранённого файла, восстановление двух вкладок после сбоя renderer и замеры проекта 1024×1024 с 24 слоями.
- `npm run test:visual` — матрица 300 состояний пяти страниц и сравнение с 50 эталонными снимками Windows/Electron 34. Эталоны обновляются отдельной командой `npm run test:visual:update` после просмотра изменений.
- `npm run audit` — проверка синтаксиса JS, относительных импортов, HTML ID, локальных ссылок, JSON, контрольных сумм PNG и сигнатур шрифтов. Результат: `docs/audit-inventory.json`.
- `npm run test:menus` — сценарии zMenu в Electron: родной YAML, действия, страницы, разделение общих кнопок, сохранение .mlst, импорт, отмена и компоновка окон.

## Конструктор меню и утилиты

В типе проекта «Конструктор меню» выбирается DeluxeMenus или zMenu. Проект .mlst хранит выбранный плагин и его исходную конфигурацию. Старые проекты DeluxeMenus открываются как раньше. Импорт YAML определяет формат, а экспорт записывает YAML выбранного плагина. Переключение формата через импорт входит в историю отмены.

Настройки находятся во вкладках «Меню» и «Кнопка». Выбор материала в библиотеке меняет выбранные слоты; если изменяется часть общей кнопки, она отделяется с сохранением действий и требований. Стрелки перемещают выделение, Ctrl+A выбирает всё меню, Ctrl+C/Ctrl+V копируют и вставляют кнопки. Неверный ввод можно отменить кнопкой в сообщении об ошибке или Escape.

Для zMenu доступны страницы предпросмотра, предмет заполнения, тип кнопки, переход на другую страницу, обновление в миллисекундах и действия в родном формате YAML. Дополнительные условия и параметры редактируются через YAML и сохраняются после визуальных изменений. Матрица zMenu после визуального редактирования преобразуется в явные слоты, чтобы старое размещение не возвращало перемещённые кнопки. Плейсхолдеры, права, условия и серверные интеграции исполняются плагином на сервере. Для нестандартных инвентарей показана схема номеров слотов.

Конфигурация zMenu сохраняется в `plugins/zMenu/inventories/`; команды-алиасы настраиваются средствами zMenu. Конфигурация DeluxeMenus регистрируется в разделе `gui_menus` его `config.yml`. Форматы сверены с официальными руководствами [zMenu](https://docs.groupez.dev/zmenu/configurations/buttons/button/) и [DeluxeMenus](https://wiki.helpch.at/helpchat-plugins/deluxemenus).

Small Caps и генератор градиента доступны из главного меню и меню редактора, не создают проектов и сохраняют введённые значения в пределах сессии. Генератор градиента показывает цветной предпросмотр с выбором фона и готовый код для копирования. Капитель показывает результат без дублирующего предпросмотра, поддерживает русский алфавит и English, выбор алфавита и обратное преобразование. Префиксы сохраняются как редактируемый проект и экспортируются в PNG.

## Структура

| Каталог | Назначение |
| --- | --- |
| `src/main` | Окна Electron, IPC, запись файлов и Discord RPC |
| `src/preload` | Изолированный мост между страницами и Electron |
| `www/js/core` | Проекты, настройки, история, автокопии и кеш превью |
| `www/js/graphics` | Слои, композиция, генерация кнопок и экспорт PNG |
| `www/js/tools` | Инструменты редактора |
| `www/js/ui` | Компоненты интерфейса |
| `www/js/windows` | Контроллеры отдельных окон |
| `www/js/utils` | Палитры, атласы символов и каталог предметов |
| `www/css`, `www/assets` | Material 3, изображения и локальные ресурсы |
| `tests`, `scripts` | Проверки и обслуживающие команды |
| `docs` | Отчёт аудита и инвентаризация |

Оформление основано на принятом интерфейсе 1.2.5. Общие компоненты используются во всех пяти окнах и внутренних диалогах: [правила и проверки интерфейса](docs/interface-style.md). Компоненты Material Web и экспериментальная Expressive-адаптация удалены. Исправления хранения, истории и инструментов сохранены. Интерфейс использует Google Sans; Material Symbols поставляются локально. Источник базового оформления: [docs/interface-rollback.md](docs/interface-rollback.md).

## Данные проектов

Формат проекта — `.mlst` (JSON с PNG слоёв и редактируемыми свойствами). Ручные сохранения выполняются последовательно с привязкой к исходной вкладке. Черновики Electron хранятся в приватной папке данных приложения, резервные браузерные хранилища — IndexedDB и localStorage.

Перед переключением документа завершаются активный штрих, редактирование текста и плавающее выделение. Автокопия не считается ручным сохранением файла. История отмены ограничена числом действий и бюджетом памяти 64 МБ на проект.

Восстановление выбирает самую свежую доступную копию из файлового и браузерных хранилищ. Индекс черновиков пересоздаётся по файлам при повреждении или незавершённом обновлении. Открытие нового документа не удаляет старые несохранённые автокопии. Обычный импорт получает собственный идентификатор восстановления.

Предел загрузки: сторона холста 4096 px, 512 слоёв, суммарно 64 млн пикселей с учётом мастер-изображений. Дополнительные ограничения защищают декодирование изображений и экспорт увеличенных PNG.

Подробности аудита: [docs/audit.md](docs/audit.md). Текущие проверки, результаты и ограничения: [docs/regression-checks.md](docs/regression-checks.md).

## Выпуск и автообновления Windows

Исходный код хранится в приватном репозитории `Nagivka/MollyStudio`. Автообновления NSIS публикуются отдельными GitHub Releases в публичном репозитории `Nagivka/MollyStudio-Updates`; он должен содержать только установщик, `.blockmap` и `latest.yml`, без исходных файлов. Portable-сборка не проверяет автообновления и обновляется вручную.

В приватном репозитории откройте **Settings → Secrets and variables → Actions** и добавьте секрет `UPDATES_REPO_TOKEN`. Это fine-grained токен с доступом только к `Nagivka/MollyStudio-Updates` и разрешением **Contents: Read and write**. Не сохраняйте токен в исходниках, `package.json` или workflow.

Для выпуска установите новую версию в `package.json` и `package-lock.json`, отправьте изменения в приватный репозиторий и поставьте тег вида `v1.3.1`. GitHub Actions запустит `npm test`, соберёт NSIS-установщик и отправит только три файла обновления в публичный репозиторий. Приложение проверяет обновление через 15 секунд после запуска, скачивает его в фоне и предлагает перезапуск.
