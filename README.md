# MollyStudio

Редактор Minecraft GUI, пиксельной графики, префиксов и 3D-надписей для Windows 10/11 x64. Разрабатываемая версия **1.4.5** (Windows **1.4.5.0**), платформа **Electron 45**. Chromium и Node.js входят в готовое приложение; пользователю не нужны отдельные компоненты или интернет для запуска.

## Разработка

Публикация готовых сборок через GitHub Actions: [порядок выпуска](docs/releases.md).

Нужен Node.js 22.12 или новее. Rust, MSVC и Windows SDK не используются.

```powershell
npm install
npm start
```

Интерфейс загружается из локальных ресурсов через защищённый протокол `molly://app/`. HTTP-сервер для работы приложения не нужен. `npm start` запускает текущие исходники; установщик и portable создаются только отдельными командами.

## Структура

| Каталог | Назначение |
| --- | --- |
| `src/main` | Окна, IPC, файлы, автокопии, очередь .mlst, ассоциации Windows и Discord |
| `src/preload` | Изолированный API между интерфейсом и главным процессом |
| `src/core` | Типизированные модели документа, миграции, очередь, команды, история и геометрия |
| `src/renderer` | Текущий интерфейс, редактор, инструменты, стили и локальные ресурсы |
| `scripts` | Запуск, статический аудит, обслуживание ресурсов и сценарии проверки |
| `tests/unit` | Модульные проверки моделей и логики |
| `tests/helpers` | Общие вспомогательные средства проверок |
| `tests/visual` | Описание визуальной проверки; эталоны создаются отдельно для версии Chromium |
| `design` | Исходные материалы оформления, предоставленные пользователем |
| `docs` | Руководство, архитектура и заметки к выпуску |
| `dist` | Результаты сборки; исключены из Git |
| `.test-output` | Логи, инвентаризация и результаты проверок; исключены из Git |

Подробнее: архитектура, руководство, изменения архитектуры и проверки, заметки к выпуску, переход на Electron.

Продолжение работ: состояние проектов, память и интерфейс.

Проверка рабочих сценариев и portable.

Ядро постепенно переносится на TypeScript. Исходники `.mts` находятся в `src/core`; браузер исполняет скомпилированные `.mjs` из `src/renderer/js/core/typed`. После изменения ядра запускайте `npm run core:compile`. Перед `npm start` и упаковкой эта команда выполняется автоматически. TypeScript нужен только разработчику; новая зависимость в готовое приложение не добавляется.

## Атмосферные эффекты

Декоративные дождь, снег и осенние листья включаются в настройках внешнего вида. Доступны интенсивность, скорость, ветер, заметность и размер частиц, предпросмотр при наведении с паузой, плавная смена погоды и показ в главном меню или во всех окнах. Качество подстраивается под нагрузку; есть экономичный режим и пиксельные текстуры в Minecraft-темах. Частицы полностью скрываются только внутри точных границ элементов интерфейса, сохраняя исходную непрозрачность снаружи. На экспорт эффекты не влияют. Проверка функции: `npm run test:weather` и `npm run test:weather-occlusion`.

## Проекты и сохранение

Формат `.mlst` версии 2 сохраняет слои, исходные изображения, редактируемый текст и параметры генераторов. Проекты открываются из диалога, перетаскиванием и через Проводник. Повторное открытие выбирает существующую вкладку, а запуск второй копии передаёт путь первой. Установщик регистрирует расширение и его отдельную иконку; portable обновляет путь открытия для текущего пользователя, сохраняя существующее назначение установленной копии.

Запись использует соседний временный файл, синхронизацию и атомарную замену. SHA-256 защищает проект от перезаписи внешних изменений. Автокопии хранятся в профиле Windows, не вытесняются другими проектами и восстанавливаются независимо от индекса. Перед закрытием главный процесс ждёт окончания операций редактора и сохранения автокопий. Отмена подтверждения оставляет окно открытым.

Дисковые автокопии прежней версии импортируются без удаления исходных данных. Существующие файлы `.mlst` совместимы. Настройки и браузерные хранилища другого движка не переносятся автоматически; пользовательский профиль на диске не очищается. Удаление приложения также сохраняет проекты и автокопии.

## Возможности редактора

- GUI для Java Edition, обычный холст и редактируемые префиксы.
- 3D-надписи с моделями букв, перспективной и ортогональной камерой, материалами, кириллицей и экспортом PNG/BBModel.
- Кисть с контуром размера, ластик, заливка, пипетка, фигуры и текст.
- Прямоугольное выделение, лассо, волшебная палочка и рисование внутри маски.
- Перемещение, поворот, точные преобразования и сохранение исходного качества изображений.
- История на вкладку, слои и группы, контекстные свойства, блокировка и режимы наложения.
- Генератор кнопок, градиенты, капитель, автошейдинг и фактуры.
- Локальные ресурсы Minecraft, палитры, готовые оформления, обычные и Minecraft-темы.
- Праздничные детали по локальной дате: Новый год 31 декабря и 1 января, Хэллоуин 31 октября, Рождество 25 декабря и 7 января, дни рождения MollyStudio 25 августа и Nagivka 30 декабря. Переключатель — «Настройки → Эффекты интерфейса → Праздничные детали». Интернет не нужен.
- Предпросмотр GUI на фоне Minecraft с фиксированным масштабом 1,5×.
- GUI-заготовки Vanilla и Bedrock; кнопки JAVA, Bedrock, FLAT, OUTLINE и DOUBLE в обоих генераторах.
- 76 чистых оформлений GUI в девяти категориях: без встроенной фактуры, с поиском и отменой применения. Предпросмотры учитывают плотность экрана и сохраняют чёткие пиксели.
- Экспорт PNG, наборов префиксов, ZIP и спрайт-листов с JSON.
- Отдельные окна настроек и генераторов, переназначение сочетаний, Discord Rich Presence.
- Русский и английский интерфейс с переключением языка во всех окнах.
- Скрытая вкладка разработчика открывается семью нажатиями на номер версии; содержит локальную диагностику и служебные настройки.

Обновления установленного приложения доступны в «Настройки → О программе» и в главном меню. Проверка подписанного выпуска и целостности EXE выполняется перед установкой. Обычное закрытие не устанавливает обновления; отмена закрытия отменяет установку.

Удалённые ранее функции не возвращаются: Unicode, экспорт ресурспаков, конструктор менюшек, значки контента и утилиты Title/«Слоты».

## Проверки

Последний полный прогон и проверка установщика: [аудит от 4 ноября 2026](docs/workspace-audit-2026-11-04.md).
Последующие исправления загрузки изображений и продолжения проверок: [дополнение к аудиту](docs/audit-followup-2026-11-04.md).

`npm run check -- --resume` продолжает прерванный прогон только при совпадении контрольных сумм кода, ресурсов, тестов, конфигурации, плана команд и среды Node.js. Учитываются новые файлы без коммита. Старый отчёт без контрольных сумм или изменённые исходники запускают проверки заново. Изменения во время прогона останавливают его с ошибкой, чтобы результаты разных версий не смешивались. Документация и результаты проверок в контрольную сумму не входят.

```powershell
npm run audit
npm run typecheck
npm run core:verify
npm test
npm run check
npm run test:architecture
npm run test:performance
npm run test:workflows
npm run test:large-session
npm run test:soak
npm run test:export-errors
npm run test:visual:components
npm run test:visual:interactions
npm run test:visual:audit
npm run test:visual
npm run test:manual
```

`audit` проверяет синтаксис, локальные ссылки и ресурсы без запуска приложения. Отчёт: `.test-output/static-audit.json`. `test` запускает модульные проверки, `check` дополнительно открывает приложение для сценариев. Ручной режим использует отдельный временный профиль и настоящие диалоги Windows; ассоциации файлов и Discord отключены. `test:manual -- --resume` повторно открывает этот профиль.

`check` также проверяет типы и соответствие скомпилированного ядра исходникам. `test:performance` проверяет настоящий фоновый обработчик JSON/PNG и записывает замеры задержек, не требуя фиксированного времени на любом ПК. `test:visual:components` проверяет холст, префиксы и диагностику во всех 12 темах при масштабах 100%, 125% и 150%; эталоны не изменяет.

`test:workflows` проходит полный цикл GUI и префикса: импорт, редактирование, сохранение на диск, закрытие, повторное открытие, PNG и набор префиксов. Пиксели готовых PNG сверяются с композитом документа. `test:large-session` измеряет память нескольких больших вкладок, включая процессы Electron, и проверяет освобождение объектов. `test:export-errors` проверяет сохранность проекта и повтор экспорта после отказа записи. Все три сценария входят в `check`.

`test:visual:interactions` дополнительно проверяет открытое меню, экспорт с ошибкой ввода и диалог фактуры: 12 тем, русский/английский язык и три размера/масштаба окна. `npm run check:distribution` выполняет проверку существующей папки `dist/win-unpacked` без сборки: проверяет наличие runtime и сравнивает упакованный код с текущими исходниками. Устаревшая сборка считается непрошедшей проверку. Этот сценарий не заменяет запуск на чистой Windows.

После отдельного разрешения пользователя проведён аудит Electron с модульными проверками и сценариями приложения в изолированных временных профилях. `test:visual:audit` проверяет геометрию всех тем и сохраняет снимки без изменения эталонов. `test:visual` сравнивает с отдельно утверждёнными эталонами текущего Chromium; старые снимки другого движка для этого не подходят. Обновлять эталоны можно только после просмотра результата.

## Сборка

```powershell
npm run build           # папка приложения без установщика
npm run dist:nsis       # установщик Windows x64
npm run dist:portable   # самостоятельный portable EXE Windows x64
```

Сборка запускается отдельной командой и не выполняется при `npm start`. `electron-builder.cjs` включает только production-код `src/main`, preload, интерфейс и его ресурсы. Исходники проверок, документация, кэши, материалы `design`, Git и секреты в пакет не входят. Сценарий управления тестовыми окнами исключён из дистрибутива. Локальная сборка ничего не публикует. Обновления установленной версии и отдельный workflow публикации описаны в [порядке выпуска](docs/releases.md).

Приложение содержит собственный Chromium, поэтому не требует установленного браузерного движка. Его размер определяется в том числе Electron; размер прежней тонкой оболочки не является ориентиром для самостоятельного дистрибутива. Результаты последней подготовки portable описаны в отчёте.

Portable дополнительно сжимается без удаления содержимого через BCJ2/LZMA2 и собственный небольшой NSIS-запускатор со встроенным декодером. Сборка отклоняет EXE размером от 100 000 000 байт. Подробности и результаты: уменьшение portable.

Шрифт значков содержит все используемые интерфейсом символы; полный оригинал сохранён вне дистрибутива. После добавления значков следуйте [инструкции пересборки](design/font-sources/README.md). `npm run test:fonts` сравнивает их отрисовку с исходником попиксельно. Зависимости Python нужны только для обслуживания ресурса, пользователю приложения они не требуются.

### Чистая Windows

Для установочной версии: `npm run test:installed-sandbox:prepare`. Возвращённая `.wsb` проверяет установку 1.4.1.0, затем переход на текущую версию. Обе версии должны находиться в `dist`. Для одной текущей версии используйте `npm run test:installed-sandbox:prepare -- --current-only`. После открытия `.wsb` сохраните тестовый рисунок в `C:\MollyResults\fixture.mlst`; файл `upgrade.request` в папке результатов разрешает переход на новую версию. Проверьте сохранность рисунка, экспортируйте `Clean Windows.png` в «Документы» и создайте `uninstall.request`. `npm run test:installed-sandbox:verify` проверяет установщик, ассоциацию, сохранённые пиксели и удаление программы с сохранением данных. Подробности и ограничения — в [порядке выпуска](docs/releases.md).

`npm run test:sandbox:prepare` готовит отдельную папку проверки и `.wsb` для текущего portable. Откройте возвращённую конфигурацию Windows Sandbox: приложение запустится без аргументов, сеть и vGPU отключены, проекты и настройки основного Windows не подключаются. В гостевой системе не устанавливаются Node.js, npm или Java. `--software` после `--` предназначен только для отдельной диагностики; такая попытка не подтверждает обычный запуск.

Сохраните тестовый GUI и PNG с одинаковым именем в `C:\MollyResults` либо в стандартную папку «Документы» гостевой системы: сценарий скопирует созданные там файлы в отчёт. Пустой файл `reopen.request` в папке результатов запускает сохранённый проект через ассоциацию `.mlst`; перед этим закройте вкладку и после запуска проверьте, что проект снова открылся. `npm run test:sandbox:verify` сверяет SHA-256 EXE, свежесть гостевых отчётов, отсутствие внешних runtime и сети, регистрацию ассоциации и пиксели сохранённого GUI/PNG. Результат остаётся в папке этого запуска; предыдущие отчёты не заменяются новым результатом. Успешный smoke-тест не заменяет проверку всех версий Windows и видеодрайверов.
