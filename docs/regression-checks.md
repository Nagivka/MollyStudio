## Исправления

- Восстановление сравнивает время записи во всех доступных хранилищах: устаревший файл больше не скрывает более свежую браузерную копию после отказа записи на диск.
- Файловое хранилище черновиков вынесено в `src/main/recoveryStore.js`. Операции последовательны в основном процессе и используют атомарную запись.
- Индекс сверяется с размером и временем изменения файлов; запись, завершённая до сбоя обновления индекса, снова появляется с актуальными названием и датой. Повреждённый индекс перестраивается.
- Удалён автоматический сброс черновиков после 100 документов. Проверены 101 копия и повторное создание хранилища.
- Зарезервирован идентификатор `index`; чтение, запись и удаление защищены от различий только в регистре на Windows. Импортированные проекты получают новые идентификаторы; восстановление сохраняет исходный.
- Выбранный инструмент сообщает `aria-pressed`; алиас трансформации корректно выделяет кнопку перемещения. Состояние генератора не затрагивается.
- Исправлена обнаруженная ревью ошибка импорта лимита размера в основном процессе. Тесты выполняют реальные файловые IPC-обработчики `main.js` в VM, изолируя жизненный цикл окон и Discord.

## Автоматические проверки

| Команда | Проверено | Результат |
| --- | --- | --- |

| `npm run test:scenarios` | Составные операции и восстановление после сбоя renderer | 12/12 |
| `npm run test:visual` | 10 тем × 5 страниц × 2 размера × 3 масштаба; 50 сравнений PNG | 300/300 |
| `npm run audit` | Синтаксис, ссылки, JSON, PNG и шрифты; 966 файлов | Ошибок нет |

Модульные проверки аварийной записи завершают собственный дочерний процесс в трёх точках: частичная запись временного файла, синхронизация перед переименованием и завершённое переименование. Результат — целый старый или целый новый JSON. Отдельный Electron-сценарий аварийно завершает собственный renderer при ожидающей записи IPC, затем проверяет завершение записи главным процессом и восстановление обоих документов в новом renderer.

Цепочка инструментов: выделение → перемещение → изменение размера → фиксация → отмена/повтор с побайтовым сравнением пикселей → масштабирование объекта и отмена → градиентный текст → сохранение → чтение фактического `.mlst` с диска и повторное открытие с редактируемым текстом.

Тесты используют собственные временные профили и файлы. Родительский процесс удаляет профиль после выхода Electron. Заглушки диалогов и Discord не проверяют взаимодействие с ОС или внешней службой. ESLint, Vitest, Prettier и TypeScript не настроены; синтаксис и локальные ссылки проверяет `npm run audit`.

## Визуальная матрица

Пять страниц: главное меню, редактор, настройки, создание проекта, генератор кнопок. Темы: dark, oled, midnight, forest, amethyst и пять light-вариантов. Размеры содержимого окна: 1280×800 и 760×780. Масштаб Chromium: 100%, 125%, 150%; это отдельная проверка zoom Electron, а не расширение списка настроек плотности интерфейса.

Проверяются загрузка страницы, применение темы, отсутствие горизонтального переполнения корневого документа, место под стрелку select, контраст текста карточек тем не ниже 4,5:1 и расположение основной кнопки целиком в окне. В редакторе используются длинные имена проекта и слоя, открыты свойства градиентного текста. В генераторе включён градиент.

Эталоны находятся в `tests/visual/baselines/win32-electron34`: 50 PNG для 1280×800, 100%. Сравнение допускает разницу каналов до 16; тест падает, если существенно изменилось более 0,01% пикселей. Ошибки, актуальные кадры и изображения различий записываются в игнорируемый каталог `.test-output/visual`.

`npm run test:visual:update` явно заменяет эталоны. После обновления нужно просмотреть снимки и выполнить обычный `npm run test:visual`, чтобы проверить воспроизводимость. Для другой платформы или основной версии Electron требуется собственный набор эталонов.

Снимки детерминированы: масштаб устройства 1, анимации и мигающий курсор выключены, внешняя сеть заблокирована. Локальные иконки и игровые атласы настоящие; Google Sans из Google Fonts при этом заменяется системным запасным шрифтом. Эти эталоны не доказывают корректность загрузки Google Sans из сети и плавность анимаций.
