# Выпуск MollyStudio

Исходники: **Nagivka/MollyStudio**, приватный репозиторий. Установщик и файлы обновления: **Nagivka/MollyStudio-Releases**, публичный репозиторий. Не меняйте видимость исходников. Публичные архивы Source code относятся только к репозиторию релизов.

## Однократная настройка

В приватном репозитории уже есть окружение `UPDATES_REPO_TOKEN` с одноимённым секретом. В Settings → Environments → UPDATES_REPO_TOKEN проверьте/обновите этот секрет: fine-grained GitHub token с доступом только к `MollyStudio-Releases`, разрешение Contents: Read and write. Не добавляйте токен в исходники, приложение или публичный репозиторий. Установите срок действия и обновляйте секрет до его истечения. Job публикации использует это окружение; проверочная сборка доступа к нему не получает.

`GITHUB_TOKEN` используется только для чтения приватного репозитория. Repository secret `UPDATES_SIGNING_KEY` содержит закрытый ключ Ed25519. Открытый ключ закреплён в `src/main/update-security.cjs`. Перед публикацией ключи сверяются. Подпись манифеста защищает обновления и не является сертификатом Authenticode для доверия Windows.

Workflow **Check release repository access** проверяет токен и соответствие ключа подписи без изменения релизов. Значения секретов не выводятся в лог и не включаются в приложение.

Настройка выполнена 29 октября 2026 года: отдельный fine-grained токен **MollyStudio release publishing**, только `MollyStudio-Releases`, Contents: Read and write и обязательные Metadata: Read-only. Секрет обновлён и проверен в Actions. Срок действия — **27 января 2027**; перед этой датой замените секрет новым ограниченным токеном.

## Проверочная сборка

Actions → **Build Windows installer** → Run workflow. Оставьте Publish выключенным. Проверки и сборка NSIS выполняются без секрета публикации. Приватный артефакт хранится семь дней; содержит установщик, `.blockmap`, `.sha256` и `latest.yml`.

## Новая версия

Portable **1.4.0.0** уже опубликован вручную под тегом `v1.4.0`. Установочная версия с обновлятором начинается с **1.4.1.0**. Существующий публичный релиз не перезаписывается.

1. Измените `package.json` и `package-lock.json`: например, `1.4.2`. В `electron-builder.cjs` установите `buildVersion: '1.4.2.0'`. Обновите проверку версии в `tests/unit/distribution.test.mjs`.
2. Создайте `releases/1.4.2.md` с изменениями для пользователей (до 8000 символов).
3. Отправьте изменения в приватный репозиторий. Создайте там тег `v1.4.2` на проверенном коммите и отправьте тег. Либо запустите workflow вручную с Publish на нужной ветке.
4. Workflow проверяет типы, ядро, модульные тесты, аудит, запуск Electron и сценарии обновления, затем собирает NSIS. Параллельно выполняются нативные проверки и сборки Mac/Linux на x64 и arm64. Публикация ожидает успеха всех платформ.
5. Job публикации подписывает манифест со SHA256/SHA512, версией, размером каждого файла и заметками к выпуску. Windows-набор: установщик, `.blockmap`, `.sha256`, `latest.yml`, `release-manifest.json`. Нативные пакеты добавляются по фиксированному списку имён после проверки версии, платформы, размера и SHA256 из отчёта сборки. Mac без постоянной подписи публикуется только для ручной установки. После проверки размеров и SHA256 на GitHub релиз становится публичным.

Существующий релиз автоматически не перезаписывается. При ошибке загрузки остаётся черновик для проверки; перед повторным выпуском проверьте его вручную. Если токен отсутствует или истёк, публикация завершится ошибкой, но приватный артефакт сохранится.

## Поведение обновлятора

Форматы, отдельные каналы архитектур, ограничения Mac-подписи и ручное обновление системных пакетов Linux: [совместимость](platform-compatibility.md). Существующий Windows-канал сохранён для ранее установленных версий.

Обновления работают в установленной Windows x64 версии. Проверка начинается в фоне сразу при запуске и затем повторяется каждые шесть часов. В «Настройки → О программе» можно проверить вручную, отключить автоматическую проверку или включить фоновую загрузку (по умолчанию выключена). Проверка обращается только к публичному GitHub Releases; проекты, настройки и токены аккаунта не передаются.

Проверка при запуске выполняется даже после недавней проверки в предыдущем сеансе и не задерживает открытие окна. Повторный запуск службы внутри того же процесса не дублирует запросы и таймеры. Если автоматическая проверка отключена пользователем, служба не обращается к сети при запуске. При ошибке фоновая проверка повторяется через 15 минут. Временные сетевые сбои допускают до трёх запросов с задержкой; ошибка подписи, лимит GitHub и отсутствующий выпуск не повторяются немедленно. Вся проверка ограничена минутой. Загрузка отменяется после двух минут без прогресса либо часа общей длительности. Отмена загрузки подавляет автоматический повтор для этой версии; повторное включение автоматической загрузки разрешает её снова.

Перед загрузкой проверяются подпись Ed25519 и метаданные. После загрузки проверяются размер, SHA256 и SHA512 EXE. Старые версии и prerelease не предлагаются. Установщик проверяется ещё раз перед запуском. Изменённые или неподписанные файлы блокируются.

Установка требует нажатия «Установить и перезапустить». Обычное закрытие не запускает установщик. Используются существующие очереди документов, атомарных записей и сохранения автокопий. Отмена закрытия или ошибка сохранения оставляет редактор открытым и отменяет установку. Настройки, `.mlst` и каталог автокопий не удаляются.

С portable 1.4.0.0 нужно один раз перейти на установщик 1.4.1.0 вручную. Уже выпущенная portable не может получить обновлятор без замены программы.

Ссылка для форума всегда одна: https://github.com/Nagivka/MollyStudio-Releases/releases/latest

5 ноября 2026 опубликована Windows x64 **1.4.5.0**: установщик, blockmap, SHA256, latest.yml и подписанный release-manifest.json. Размер EXE — 122 829 750 байт; SHA256 — `e91f5b55dd262de84ab01104395e69099e4931b0cc3850d790cb67fd8c0f22e4`. Публичные метаданные, подпись и совместимость с прежним Windows-обновлятором проверены после публикации. Отчёт: `.test-output/published-update-1.4.5.json`.

Hosted Actions заблокированы ограничением платежей/расходов. Публикация выполнена одноразовым локальным Windows runner с проверкой точного SHA256 установщика и существующим ключом из Actions secret. Runner не устанавливался службой, удалён из GitHub после единственного задания; временный workflow удалён. Сборки macOS/Linux в этот выпуск не вошли: их hosted jobs не начали выполнение. Для следующих выпусков восстановите доступ к hosted Actions либо используйте доверенные нативные runner соответствующих платформ.

Electron включает renderer-код в приложение. Приватность GitHub не делает JavaScript в EXE недоступным для анализа.

## Локальная проверка установщика

`npm run dist` собирает EXE без публикации. `npm run check:distribution` сравнивает ресурсы `app.asar` с текущими исходниками и проверяет отсутствие служебных файлов; сам по себе этот результат не подтверждает запуск на чистой Windows.

`npm run test:installed-sandbox:prepare` создаёт отдельную конфигурацию Windows Sandbox для реальной установки 1.4.1.0 и перехода на текущую версию. Установщики обеих версий нужны в `dist`. Для проверки только текущего установщика: `npm run test:installed-sandbox:prepare -- --current-only`. Параметр `--fixture <путь>` использует заранее сохранённый тестовый `.mlst`. Сеть, vGPU и буфер обмена гостевой системы отключены; основная папка профиля пользователя не подключается.

Откройте созданную `.wsb`, нарисуйте тестовый объект и сохраните проект в `C:\MollyResults\fixture.mlst`. Создайте `upgrade.request` в указанной папке результатов на основном ПК: сценарий закроет старую версию, установит новую и откроет проект через ассоциацию `.mlst`. В режиме `--current-only` этого шага нет. Проверьте рисунок и экспортируйте `Clean Windows.png` в «Документы» гостевой системы. Сценарий скопирует его в результаты. Затем создайте `uninstall.request`: программа закроется, а установщик удалит файлы приложения, сохранив проект и профиль.

`npm run test:installed-sandbox:verify` проверяет последний запуск. Можно передать путь к JSON предыдущего запуска после `--`. Проверяются версия и SHA256 EXE, отсутствие дополнительных runtime и сети, ассоциация `.mlst`, попиксельное совпадение PNG с проектом, удаление EXE и сохранность данных. Принудительное завершение гостевого приложения записывается отдельно и считается неуспешным закрытием.

Этот сценарий проверяет переход установщиком. Проверки `npm run test:updates` отдельно загружают подписанные метаданные и EXE настоящим `electron-updater` с локального HTTP-сервера; исполнение заменяется тестовым обработчиком. Полный публичный переход через GitHub проверяется только после разрешения на публикацию новой версии.
