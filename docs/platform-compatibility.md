# Совместимость с операционными системами

MollyStudio 1.4.5 / сборка 1.4.5.0. Исходники открыты в `Nagivka/MollyStudio`. Доступные пользователям пакеты перечислены в GitHub Releases; наличие конфигурации платформы само по себе не подтверждает выпуск проверенной сборки.

## Платформы и пакеты

| ОС | Архитектура | Пакеты |
| --- | --- | --- |
| Windows 10/11 | x64 | Установщик NSIS, portable |
| macOS 13 и новее | Intel x64, Apple Silicon arm64 | DMG, ZIP с приложением |
| Linux с графическим рабочим столом | x64, arm64 | DEB, RPM, AppImage, tar.gz; отдельная сборка Flatpak |

Нижняя граница macOS соответствует [Electron 44 и новее](https://www.electronjs.org/blog/electron-44-0). Linux CI использует Ubuntu 24.04 на обеих архитектурах; совместимость со всеми дистрибутивами и оконными менеджерами этим не подтверждается. Linux-пакет требует стандартные системные библиотеки GTK/NSS/ALSA и графическую сессию. DEB указывает зависимости и устанавливает ассоциацию `.mlst`, значки, desktop entry и штатный профиль AppArmor. Для AppImage может потребоваться FUSE и разрешённые ядром пользовательские пространства имён; в Ubuntu с ограничением user namespaces предпочтителен DEB. Приложение не запускается от root, sandbox сохраняется.

Chromium и Node.js включены в пакеты. Отдельная установка Node.js или браузера пользователям не требуется. 3D-генератор требует доступный WebGL; если графический драйвер его не предоставляет, редактор показывает причину и сохраняет последний корректный документ вместо падения.

## Системное поведение

- На Mac используются штатные кнопки окна и системное меню. Закрытие последнего окна оставляет приложение в Dock; повторная активация создаёт окно. Cmd+Q проходит через сохранение автокопий и подтверждение; отмена сохраняет рабочий редактор.
- Сочетания редактора используют Command на Mac и Control на Windows/Linux. Сохранённые назначения клавиш остаются совместимыми. Для редактирования текста на Mac Option перемещает по словам, Command — по границам строки или документа. Control+щелчок не рисует на холсте.
- Системное меню Mac синхронизирует переназначение и отключение сочетаний с настройками, включая сохранённые назначения при старте. Одиночные буквы остаются сочетаниями холста и не перехватываются системным меню у ввода текста.
- На Linux пути чувствительны к регистру. `Menu.mlst` и `menu.mlst` не объединяются. Файлы с кириллицей и пробелами, обычные аргументы запуска и `file://` обрабатываются очередью открытия. HTTP-ссылки не принимаются как проекты.
- Проекты `.mlst`, ресурсы, PNG, ZIP и настройки генераторов имеют общий формат для всех платформ. Автокопии находятся в системном каталоге профиля MollyStudio.
- Значки приложения и `.mlst` подготовлены в PNG/ICO/ICNS. Ассоциации Mac/Linux создаёт пакет, обращения к Windows Registry выполняются только на Windows.

## Подпись и обновления

| Пакет | Обновление |
| --- | --- |
| Windows NSIS | Существующий подписанный манифест Ed25519 и установка после подтверждения |
| Linux AppImage | Отдельный подписанный манифест и метаданные для архитектуры |
| Linux DEB / tar.gz | Ручная установка нового пакета; интерфейс сообщает об этом |
| Linux RPM | Установка нового RPM штатным менеджером пакетов |
| Linux Flatpak | Обновление через Flatpak-репозиторий при его подключении; локальный bundle заменяется вручную |
| Mac с постоянной подписью Developer ID | Отдельный ZIP-канал и подписанный манифест для архитектуры |
| Mac с ad-hoc подписью | Автоматическая проверка, скачивание DMG через браузер и ручная замена приложения |

Нельзя заменить Apple Developer ID самоподписанным сертификатом. Для обычного распространения через интернет нужны [подпись Developer ID и нотариальная проверка Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution). [Squirrel.Mac требует подпись для автоматических обновлений](https://www.electronjs.org/docs/latest/api/auto-updater/). Без предоставленных Apple-данных CI собирает явно обозначенный ad-hoc вариант для проверки, без обещания бесшовного прохождения Gatekeeper. Защита macOS не отключается.

Подготовлены необязательные Actions secrets: `MAC_CSC_LINK`, `MAC_CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`. Пустые значения отсутствующих секретов не передаются подписывателю как путь к сертификату. Закрытый ключ публикации обновлений доступен только job публикации, а не проверкам платформ.

## Сборка и проверки

Разработчику нужен Node.js 22.12+; CI использует Node.js 24. Нативные пакеты собираются на соответствующей ОС:

```sh
npm ci
node node_modules/electron/install.js
npm run typecheck
npm run core:verify
npm test
npm run audit
npm run test:platform
npm run dist                 # текущая ОС и архитектура
npm run dist -- darwin arm64 # на macOS
npm run dist -- linux x64    # на Linux
npm run dist:flatpak         # отдельно, после установки Flatpak SDK и BaseApp
```

## Расширение Linux от 5 ноября

Сборка Linux теперь создаёт также RPM на x64 и arm64. RPM проходит проверку контрольной суммы перед включением в публикацию, как DEB и архив. Установка нового RPM не удаляет пользовательский профиль.

Для Fedora, openSUSE, Arch, NixOS и других систем с Flatpak подготовлен отдельный bundle на runtime `org.freedesktop.Platform/25.08` и `org.electronjs.Electron2.BaseApp/25.08`. Zypak сохраняет изоляцию процессов Chromium. Доступны X11, Wayland, GPU и звук. Разрешён доступ к домашней папке и точкам монтирования `/media`, `/run/media`, `/mnt`, чтобы работали проекты, автокопии и атомарное сохранение на внешние диски. Остальные пути требуют разрешения Flatpak. Данные профиля Flatpak находятся отдельно от обычной установки. Flathub-публикация и собственный Flatpak-репозиторий не настроены; встроенный AppImage-updater не заменяет Flatpak.

Подготовка сборочной машины:

```sh
flatpak remote-add --user --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
flatpak install --user flathub org.freedesktop.Platform//25.08 org.freedesktop.Sdk//25.08 org.electronjs.Electron2.BaseApp//25.08
npm run dist:flatpak
flatpak install --user dist/MollyStudio-*.flatpak
flatpak run ua.nagivka.mollystudio
```

Новый ручной workflow `linux-distributions.yml` собирает Linux-пакеты и запускает упакованный редактор в контейнерах Ubuntu 22.04, Debian 12/13, Fedora 43, Arch и openSUSE Tumbleweed. Проверяется наличие библиотек, открытие MLST, редактирование, PNG и закрытие. Приложение работает от непривилегированного пользователя; SUID sandbox настраивается только в одноразовом CI-контейнере. Для его работы контейнеру явно предоставлены SYS_ADMIN и расширенный seccomp; на пользовательском ПК такие изменения не выполняются. Контейнерный X11 не заменяет проверку реальных GNOME/KDE и драйверов. Flatpak jobs отдельно проверяют создание и установку bundle на x64/arm64; полноценная интерактивная работа внутри Flatpak ими пока не подтверждается.

**Статус:** конфигурации, контрольные суммы и модульные проверки выполнены на Windows. Новый Linux workflow ещё не запускался: доступные GitHub Actions ранее блокировались оплатой/лимитом аккаунта, локального Linux runtime здесь нет. Новые RPM/Flatpak не объявляются собранными или проверенными на дистрибутивах.

Ни один формат не гарантирует работу на буквально всех дистрибутивах: нужны поддерживаемая архитектура, графическая сессия, совместимое ядро и драйвер. Нативные пакеты Electron требуют glibc; для musl-систем и NixOS предпочтителен Flatpak с его runtime. Старые неподдерживаемые системы, 32-битный Linux и системы без WebGL не получают обещания полной функциональности 3D.

`.github/workflows/platform-compatibility.yml` использует macOS 26 на Intel и Apple Silicon, а также Ubuntu 24.04 на x64 и ARM64. Включены модульные проверки, типы, аудит ссылок с точным регистром, запуск Electron, системные сочетания, жизненный цикл, полный цикл GUI/префикса, восстановление WebGL, сборка и запуск готового пакета.

На macOS сценарий проверяет DMG, распаковывает ZIP, проверяет подпись приложения и запись `.mlst` в `Info.plist`. После закрытия окна он передаёт другой проект через системную команду `open` и проверяет, что существующий процесс открыл его. На Linux сценарий проверяет MIME-тип в установленном DEB и открывает `file://` с кириллицей и пробелами, как при запуске через `.desktop`. На обеих платформах он сохраняет проект, экспортирует PNG, сравнивает пиксели и проверяет закрытие окна.

Windows-задание создаёт синтетические GUI, префикс и 3D-надпись. Linux и macOS открывают эти же файлы, сохраняют и сравнивают параметры. Для GUI и префикса сравнение PNG попиксельное. Для 3D отдельно проверяются совпадение геометрии и средняя разница цвета с учётом сглаживания на разных GPU. После проверки каждую сцену меняют через редактор и сравнивают изменившийся экспорт.

Wayland проверяется в Weston на Ubuntu с отключённым для приложения `DISPLAY`. Сценарий проверяет нативное окно в масштабе 125%, системный буфер обмена, обработчик перетаскивания PNG и открытие через установленную запись `.desktop`. Это проверка Weston, а не ручное тестирование оболочек GNOME и KDE.

Сценарий AppImage использует встроенный режим `extract-and-run`, сохраняет sandbox и запускает реальные исполняемые файлы до и после замены. Для проверки используются разные байты двух копий одного пакета CI. Сценарий моделирует ошибку контрольной суммы и отказ при планировании перезапуска, затем проверяет, что прежний файл запускается. После успешной замены сохраняется одна копия `.previous`. Проверку публичного обновления между двумя версиями и FUSE-режима этот сценарий не выполняет.

Отдельный workflow `appimage-upgrade.yml` собирает две временные версии `0.0.1` и `0.0.2` на Linux x64 и arm64. В тестовые пакеты явно включается загрузчик `scripts/lib/appimage-update-entry.cjs`. Обычная конфигурация сборки его не включает. Сценарий использует настоящий `AppImageUpdater`, локальный HTTP-сервер и временный ключ Ed25519. `UpdateService` проверяет подписанный манифест, скачивает новую версию, закрывает редактор и перезапускает заменённый AppImage. Новый процесс подтверждает свою версию, сохранённый слой и автокопию несохранённого слоя. Подмена адреса сервера и ключа существует только в загрузчике тестового пакета. Проверка выполняется через `extract-and-run`, без публичного выпуска и обращения к настоящему серверу обновлений. На обеих архитектурах она прошла в [прогоне `41893894738`](https://github.com/Nagivka/MollyStudio/actions/runs/41893894738).

`mac-hardware-validation.yml` предназначен для отдельного доверенного Mac с меткой `mollystudio-qa` и активным графическим сеансом. Режим `macos-13` сверяет версию системы и запускает готовое приложение на Ventura. Для этого сценария нужна macOS 13.5 или новее в ветке 13, поскольку инструменты сборки используют [Node.js 24](https://github.com/nodejs/node/blob/v24.x/BUILDING.md#platform-list). Режим `intel-webgl` проверяет архитектуру, исключает Rosetta и требует работающий WebGL.

Если для Mac предоставлены данные подписания, сборка проверяет, что приложение действительно подписано сертификатом Developer ID Application. При включённой нотариальной проверке сборка также проверяет прикреплённый билет. Для реального обновления нужны два выпуска, подписанные одной идентичностью Apple. [Требования Apple](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)

[Инструкция по выбору пакета и переносу проектов](install.md).

У виртуального Intel Mac проверка перебирает графические backend и сохраняет результат в `.test-output/ci-graphics.json`. Если ни один не предоставляет WebGL, это явно отмечается в отчёте и GitHub Step Summary: проверяется понятное сообщение, сохранность документа, повтор открытия и работа обычного холста. Рендеринг 3D и восстановление WebGL на таком Intel-сервере **не считаются проверенными**; для них нужен Intel Mac с доступным графическим драйвером. На Apple Silicon и обеих Linux-архитектурах выполняется полный сценарий 3D. Переключатели программной графики применяются только внутри изолированного CI и не входят в запуск приложения. Во всех сценариях Electron sandbox включён явно; Playwright не получает разрешение отключать его автоматически.

Отчёты и дистрибутивы сохраняются в Actions artifacts на семь дней. Release workflow ожидает успешных нативных job и Windows job, затем передаёт только фиксированный набор проверенных пакетов и метаданных в публичный репозиторий релизов. Неизвестные ZIP, исходники, кэши и ключи не включаются в публикацию.
